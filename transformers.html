Understanding Transformer Architecture: From Tokens to Attention

You type “The bank approved my…” into a language model. It suggests “loan.” Sensible. But how did it know that “bank” probably meant a financial institution rather than the edge of a river?

That question leads us into one of the most influential ideas in modern AI: the Transformer. It powers many systems that summarize documents, translate languages, answer questions and generate code. And although the mathematics can get intimidating, the intuition begins with something ordinary: words don't mean much without their neighbours.

Consider the sentence “The dog chased the ball because it was excited.” Most readers understand that “it” probably refers to the dog. Replace excited with round, and suddenly the ball becomes the likely referent. A useful language model must track relationships across a sentence, not just look at one word at a time.

Transformers are designed to construct those sensitive to context representations efficiently. Let's follow a piece of text through one, from the first token to the final prediction.

Before attention, there was a bottleneck

Earlier popular sequence models used recurrent neural networks (RNNs) and long short-term memory networks (LSTMs). These processed text step by step, carrying information from earlier tokens forward in a hidden state. That sequential dependence made training difficult to parallelize across positions and could complicate learning distant relationships.

In 2017, researchers introduced the Transformer in the paper Attention Is All You Need. Their machine-translation architecture replaced recurrence with attention mechanisms and feed-forward layers. The idea was not that every problem in language had been solved. It was that a model could examine relationships between positions without processing those positions through a recurrent chain.

The result was an architecture that proved remarkably adaptable. Today's large language models vary substantially, but attention-based Transformer blocks remain a defining building block.

Step 1: Break text into tokens

A model doesn't begin with words in the human sense. A tokenizer turns text into token IDs drawn from a fixed vocabulary. Depending on the tokenizer, a token might represent a whole word, part of a word, punctuation or a containing a space fragment.

For a simplified illustration, imagine the phrase:

The river bank was crowded

It might be represented as five tokens, but an actual tokenizer could divide it differently. Each token is assigned an integer ID. Those IDs are only identifiers, not numerical measures of meaning. Token 204 isn't inherently twice as meaningful as token 102.

Tokenization matters because the model's context window and processing costs are typically measured in tokens. It also affects how unusual names, code and multilingual text are represented. A tokenizer that turns a technical identifier into several pieces can still handle it, but the model has more pieces to reason over.

Step 2: Give each token a vector

The token ID is used to look up an embedding: a learned list of numbers. If the model's hidden dimension is 768, for example, the embedding for each position has 768 components. The precise dimensions depend on the model.

Think of embeddings as a working numerical representation, not a neat dictionary in which one coordinate means “finance” and another means “water.” Their meaning is distributed across many dimensions, and those representations change as the model processes context.

At this stage, “bank” has a starting vector. It hasn't yet been fully interpreted in relation to river. That happens through the layers that follow.

There is another problem: if we simply handed a model a bag of token embeddings, how would it know which came first? “Dog bites man” and “Man bites dog” use the same words but tell rather different stories.

Step 3: Add position information

Transformers need some mechanism for representing order. The original 2017 architecture added positional encodings to token embeddings; its paper explored sinusoidal encodings. Modern models use different approaches, including learned positional embeddings and rotary positional embeddings (RoPE).

The implementation differs, but the purpose is similar: make order and relative position available to the model.

The input to a Transformer layer is therefore more than an isolated word embedding. It carries token identity and position information. Now the interesting part begins.

Step 4: Self-attention lets tokens consult their neighbours

Suppose the model sees:

She sat by the bank and watched the boats.

When producing the representation for bank, it helps to consult boats and sat by. In a different sentence, bank might attend to loan and interest. Self-attention is a learned mechanism for combining information across token positions according to how useful other positions appear for the current one.

Imagine a group project in which every student gets a chance to ask the others for relevant information. The students aren't literally asking questions in English, but the analogy helps explain the three learned projections in attention.

Query, Key and Value without the mystery

For each input vector, the model computes three new vectors through learned linear transformations:

  • A Query (Q) expresses what information a position is looking for.
  • A Key (K) represents information that other positions can match against.
  • A Value (V) carries the information to combine if that position is attended to.

A position's query is compared with the keys of positions it is allowed to see. Higher compatibility scores usually translate into larger attention weights after normalization. Those weights determine how strongly the value vectors contribute to the position's updated representation.

This isn't a literal database query, and a high attention weight shouldn't be treated as a perfect explanation of a model's reasoning. It's a useful computational description.

The standard scaled dot-product attention equation is:

Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V

The dot products measure query-key compatibility. Dividing by the square root of the key dimension helps keep scores from becoming too large. The softmax converts scores into zero or positive weights that sum to one across the eligible positions. Multiplying by V produces weighted combinations of information.

A tiny made-up attention example

Suppose the current position is bank in our boating sentence. To keep the arithmetic easy, imagine its attention scores lead to weights of 0.60 for boats, 0.25 for sat, and 0.15 for bank itself. The model combines the three corresponding value vectors using these weights.

That does not mean real Transformers use these exact numbers, or that a single head always locks onto the obvious to a reader clue. The example simply shows what weighted combination means. In practice, attention is learned from data and spread across many heads and layers.

Step 5: Multi-head attention looks for different relationships

One attention pattern has limited room to represent every useful relationship in a sentence. The Transformer therefore uses multi-head attention: several attention operations run on different learned projections, and their outputs are combined.

In our sentence, one head might respond strongly to nearby syntax while another picks up a more distant relationship. But a head is not assigned a permanent easy to interpret job. These patterns are emergent and often messier than explanatory diagrams suggest.

After each head forms its output, the model concatenates the results and projects them back into the model's hidden dimension. The resulting vector contains contextual information assembled from several attention perspectives.

This is the architecture's defining move: each token's representation can become sensitive to other tokens, even when they are far apart in the sequence.

Step 6: Feed-forward networks do a different job

Attention gathers and mixes information across positions. What happens next is often a position-wise feed-forward network, usually a sequence of learned linear transformations with a nonlinear activation in between.

If attention is the meeting where everyone exchanges information, the feed-forward network is the part where each participant processes what they've heard. The same feed-forward weights are applied independently at each token position, though each position now contains different contextual information.

Transformer blocks also use residual connections and normalization. Residual connections help information and gradients travel through deep networks; normalization helps keep training stable. The precise arrangement of these components varies across architectures.

One block isn't usually the end of the story. Models stack many blocks, repeatedly transforming token representations. Earlier layers may capture certain local relationships, while later layers can combine information into more abstract features. Those tendencies are not rigid rules.

The original Transformer had an encoder and a decoder

The original machine-translation architecture had two major parts.

Encoder: It read the input sequence using self-attention that could consider the full available input. The output was a sequence of rich in contextual information representations.

Decoder: It generated the output sequence one token at a time. Its masked self-attention prevented positions from using future output tokens. It also used cross-attention to consult the encoder's output, allowing the generated translation to depend on the source sentence.

For translation, this makes intuitive sense. An encoder reads “Where is the station?” and the decoder produces a corresponding sentence in another language while consulting what the encoder understood.

But not every model you encounter today has that full arrangement.

Encoder-only, decoder-only and encoder-decoder models

Three common families help explain how Transformers have evolved.

Encoder-only models, such as BERT-style systems, are typically useful for tasks involving representations of input text. Bidirectional attention allows token positions to incorporate left and right context. Common applications include classification and extracting information.

Decoder-only models, including GPT-style language models, use causal attention during generation. A position can attend to itself and preceding tokens, but not future tokens. That restriction matches the next-token prediction task: the model cannot peek at the answer it is supposed to predict.

Encoder-decoder models, such as T5-style architectures, retain separate input processing and output generation components. They suit many sequence-to-sequence tasks, including translation and certain summarization setups.

The boundaries are not always perfect, and modern systems add architectural and training variations. Still, this three category classification is a very useful map.

How does a decoder-only LLM actually write a sentence?

Let's return to our opening prompt:

The bank approved my

A decoder-only model processes the tokens through its Transformer stack. At the final position, an output projection produces a score, called a logit, for each possible next token. Those logits are converted into a probability distribution. A decoding strategy selects the next token, perhaps “loan,” depending on the model and settings.

That token is appended to the context, and the process repeats to produce the following token. Generation continues until a stopping condition is met. This is why an LLM produces text sequentially at inference time, even though much of its training computation can run across many token positions in parallel.

There is no tiny person inside the network completing the sentence. Nor is it simply copying the most frequent phrase. Its learned parameters and current context shape the next-token distribution. This process can support surprisingly sophisticated behavior, but it also explains why plausible language isn't automatically reliable knowledge.

What attention does well, and what it doesn't fix

Self-attention allows direct interactions between positions, making distant dependencies easier to model than in many recurrent designs. The architecture also maps well to modern parallel computing hardware.

The trade-off is that standard full self-attention forms scores between pairs of sequence positions. For sequence length n, that score matrix scales roughly as n² in size. Efficient implementations and alternative attention methods can reduce practical memory or compute costs, but long contexts remain an engineering challenge.

And attention is not a fact checker. A model can use context effectively while still making unsupported claims. Training objectives, data quality, retrieval systems, evaluation and safety controls all matter.

The simplest way to remember the Transformer

A Transformer begins with token IDs, turns them into vectors, incorporates order, and repeatedly updates each vector using attention and feed-forward computation. For generating text, a decoder-style model converts the final representation into probabilities for the next token and repeats.

The big shift was moving from “read the sentence one step at a time” toward “learn which parts of the available context matter to each position.” That is a powerful idea, even if the details take longer than a coffee break to appreciate.

The next time a model distinguishes a river bank from a bank loan, you know the broad machinery behind the choice. It isn't looking up a fixed definition. It's building sensitive to context representations, one layer after another.
